# 二次规划与目标权重契约

本页只定义 DolphinDB `osqp` 的接口、矩阵维度、结果校验和下单前数值处理，不提供任何具体目标函数、
约束方案、资产选择或组合构造。

## OSQP 接口

`osqp` 求解标准二次规划：

```text
minimize    0.5 * x' P x + q' x
subject to  l <= A x <= u
```

Arena 当前 DolphinDB 调用顺序为：

```text
solution = osqp(q, P, A, l, u)
```

设变量数为 `n`、约束行数为 `m`：

| 对象 | 维度 | 要求 |
| --- | --- | --- |
| `P` | `n × n` | 有限、对称，并满足求解器要求的半正定条件 |
| `q` | `n` | 有限 |
| `A` | `m × n` | 有限 |
| `l` | `m` | 与 `A` 的行一一对应 |
| `u` | `m` | 与 `A` 的行一一对应，且逐项满足 `l <= u` |

`P/q/A/l/u` 如何由业务问题产生属于调用方模型，不是 Arena 契约。更换求解器时必须按新求解器的
参数定义重新映射，不能只替换函数名。

## 返回值与状态

返回值是二元 tuple：`solution[0]` 为状态字符串，`solution[1]` 为长度 `n` 的解向量。`solved` 表示
正常成功；`solved inaccurate` 只有在调用方明确允许并通过更严格的约束残差检查后才能进入下游。
其他状态一律按失败处理。

以下任一情况都不得继续下单：

- 状态不在允许集合；
- 解为空、长度不等于 `n`，或含 NULL、NaN、无穷；
- 原始约束残差超过容差；
- 解不满足下游目标接口的取值域；
- 输入维度、有限性、对称性或显式边界检查失败。

求解失败时应停止本次目标提交并记录状态。是否维持现状或采用其他预先定义的处理方式，必须由调用方
显式决定；Arena 不自动生成替代权重。

## 数值容差与非负目标

`order_target_value` 要求 `targetValue` 为有限非负数。若解向量会转换为非负目标权重，应在转换前按
统一容差 `eps > 0` 处理：

1. 校验向量长度和全部元素有限；
2. 将 `[-eps, 0)` 内的数值噪声截为 0；小于 `-eps` 的值视为无效解；
3. 若业务约束要求固定权重和，只在截断后总和大于 `eps` 时重新归一化；
4. 归一化后重新检查权重和、上下界和原始约束，因为归一化可能破坏其他约束；
5. 将权重转换为目标金额后，再次检查每个目标金额有限且非负。

不要直接把所有负值置零后继续使用，也不要在没有固定权重和约束时擅自归一化。

## 调仓执行顺序

目标值计算正确不代表订单可执行。组合级调整使用两阶段流程：

```text
读取实际持仓、可用现金和活动订单
  -> 撤销或处理冲突订单
  -> 提交目标为零和所有目标下降的订单
  -> 等待订单/成交状态更新
  -> 重新读取实际持仓、可用现金和活动订单
  -> 按实际剩余资源提交目标上升的订单
```

第一阶段不仅包含清零，也包含保留代码的减仓。卖单已提交不等于现金已释放；只有重新查询后的实际
状态可作为第二阶段预算。还应为费用、价差、取整和价格变化保留余量。

## 当前预检边界

`run_backtest` 当前会执行 Runtime Schema 校验、DSL 引用校验以及 `utils`/callbacks 编译预检，但没有
独立的优化模型静态校验工具。矩阵维度、可行性、求解状态、数值容差和目标金额必须由调用方脚本在
下单前检查；文档不把这些检查描述成服务端已提供能力。

部署版本中的函数签名可用 `describe_dolphindb_functions(["osqp"])` 查询。所有已认证用户都可用
`execute_dolphindb_script` 在只读账号和 10 分钟 Session 截止时间内验证自有最小脚本，但该工具没有
CPU、内存配额或服务端资源沙箱；它只证明脚本在当前 DolphinDB session 中执行，不证明完整回测或
业务约束正确。
